# agy-claude: Claude Code через Antigravity Proxy

> Исторический дизайн на начало работы. После разрешённой пользователем live-проверки рабочим backend для Gemini 3.8 Flash оказался `gemini-3.8-flash-tiered` с medium thinking на `daily-cloudcode-pa.googleapis.com`; модель по умолчанию изменена на Gemini 3.8 Flash. Актуальные команды и статус моделей — в README.

## Зачем

Запускать Claude Code командой `agy-claude` через локальный Antigravity Proxy, аналогично существующим `codex-claude` и `kimi-claude`, с актуальными моделями `agy`. Сейчас прокси предоставляет OpenAI `/v1/chat/completions` и Gemini passthrough, но не Anthropic `/v1/messages`; один лишь `ANTHROPIC_BASE_URL` не работает. Сам прокси сейчас не запущен.

## Результат

- Отдельный `~/.claude/agy-settings.json` по структуре `~/.claude/kimi-settings.json`: отключён Telegram-плагин, такой же режим разрешений, переменные `ANTHROPIC_BASE_URL=http://127.0.0.1:8877`, `ANTHROPIC_AUTH_TOKEN=unused`, модель по умолчанию `claude-opus-5-5`, роль Sonnet — `claude-sonnet-5-5`; fast/small роль — модель, действительно доступная через прокси. Не копировать чужой ключ или настройки провайдера. Значения контекстного окна и effort согласовать с возможностями бэкенда; не заявлять неподтверждённый контекст.
- Новая строка в `~/.bashrc`: `agy-claude` запускает `claude --dangerously-skip-permissions --settings ~/.claude/agy-settings.json`, как существующие алиасы. Аргументы после алиаса остаются доступными. Существующие JSON-настройки и алиасы не изменять.
- Прокси получает `/v1/messages` (плюс совместимый путь `/messages` при необходимости) в обоих режимах: JSON-ответ и Anthropic SSE. Поддержать реальные циклы Claude Code: `system`, `user`/`assistant` text, инструменты `tools`, `tool_use`, `tool_result` с несколькими вызовами, сохранение upstream `functionCall` ID и `thoughtSignature`, `max_tokens`, `stop_sequences`, ошибки и `usage`; потоковые события `message_start`, `content_block_start/delta/stop`, `message_delta`, `message_stop`, включая инкрементальный JSON инструмента. Не возвращать фиктивно успешный ответ при ошибке/несовместимом формате. Публичный OpenAI-маршрут должен работать как прежде. Не устанавливать новые зависимости: Python stdlib.
- Обновить `MODEL_MAP` и документацию: сохранить старые алиасы для обратной совместимости; добавить `gemini-4-argon` → `gemini-4-argon-medium`, `gemini-3.8-flash` → `gemini-3.8-flash-medium`, `claude-opus-5-5` → `claude-opus-5-5-medium`, `claude-sonnet-5-5` → `claude-sonnet-5-5-medium`. Первые три идентификатора видны в сохранённых сессиях `agy`, Sonnet ID — в установленном бинарнике; это кандидаты для backend-поля, а не подтверждение успешного вызова через прокси. Документация не должна представлять их как проверенные live. GPT-OSS 120B Medium показывается в `agy`, но его точный backend ID пока не установлен; не выдавать предположение за проверенный алиас, разрешить явный passthrough и документировать ограничение. Если проверка локальных данных или безопасный live-прогон подтвердит ID, можно добавить его и тест.
- Проверка без внешних расходов: unit/HTTP-тесты на фейковом upstream для JSON/SSE/tool round-trip/ошибок, синтаксис JSON и bash, локальный smoke Claude Code на заглушке. Реальный вызов Google требует отправки тестового текста за пределы машины; не выполнять без отдельного подтверждения. Показать пользователю, как запустить локальный прокси и как проверить запрос самостоятельно. Запускать прокси только на `127.0.0.1`.

## Не делаем

Не заменяем Claude Code другим клиентом; не меняем `kimi-settings.json`, `codex-settings.json`, `~/.claude/settings.json` или текущие провайдеры; не отключаем аутентификацию Google и не открываем прокси наружу; не создаём и не отправляем коммиты/PR без запроса. Не обещаем полной совместимости всех возможностей Anthropic API: неподдерживаемые блоки (например, загружаемые Anthropic files) должны отбрасываться только если это безопасно и явно оговорено, иначе возвращать понятную ошибку.

## Решения исполнителя

Выбрать минимальную структуру тестов и способ разделить адаптер от существующего OpenAI-кода без регрессий; определить точное соответствие вспомогательной модели из подтверждённых backend ID; при необходимости добавить локальный сервисный запуск, но не включать постоянный автозапуск без отдельного запроса. Совместимость проверять прежде всего с установленным Claude Code 2.1.305.
